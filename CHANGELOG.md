- 2026-10-13: **the project is called Mainworthy** (it was Casebook; decision 0015, issue #98). An install made before the rename is carried over by the next `mainworthy serve`: the data directory and the database file are moved (the server refuses to start while another process has the old file open), a browser's drafts, run notes and theme move to their new keys, archives exported before still import, and a report that names its case with `<property name="casebook">` still links. The deployment in `compose.coolify.yaml` keeps its stored names.

- 2026-10-13: **Changed:** whoever administers no longer makes a token for somebody else. A token for a person who exists is made by that person or by the owner of the instance, and one for the owner by the owner alone; an agent that holds `admin` makes no person and no person's token, changes no grant (`grant.set`, `grant.remove`) and forgets nobody (`actor.forget`). The refusal is `forbidden` and says who may. An agent that administers still makes projects and tokens for agents and pipelines. Before, any admin, an agent included, could mint a token for the owner and act under that name.
- 2026-10-13: the owner always has a way in. In server mode `token.revoke` refuses the last token the owner can sign in with, and `actor.forget` refuses the owner; each says what to do instead. Before, one click on Revoke in Settings locked the instance for good.
- 2026-10-13: start-up says when `MAINWORTHY_OWNER_TOKEN` cannot sign the owner in (the token was revoked, or is somebody else's) in one line on stderr, and does not bring the token back. With no token configured, a start on which the owner holds no token that works generates one and prints it as the first start does: after an import, for instance. Before, both starts looked like any other and nobody could sign in.
- 2026-10-13: the server does not start when `MAINWORTHY_OWNER` names an agent, a pipeline or the policy's own actor on the instance; the message names the variable. Before, the start gave that actor every capability.
- 2026-10-13: **Changed:** a caller that holds no grant on a project is answered as for a project that does not exist (`not_found`, "no project named <key>, or no grant on it"), in an operation and on the change stream. Before, `forbidden` there and `not_found` elsewhere told any token which project keys exist. A caller that holds a grant and lacks the capability still gets `forbidden` and the capability it lacks.
- 2026-10-13: local mode is for the machine it runs on. The owner with no sign-in is a request with a loopback Host, on a connection from a loopback address, with none of the headers a proxy or a tunnel adds (`Forwarded`, `X-Forwarded-For`, `X-Forwarded-Host`, `X-Real-IP`, `Via`, `CF-Connecting-IP`). Before, a local-mode server behind a proxy that rewrites Host made every visitor the owner. A relay that passes bytes on unchanged from the same machine still does: the server cannot see through it, and `docs/deploy.md` says not to expose a local-mode port that way. A request the browser says another site made (`Sec-Fetch-Site`) is refused in both modes, a GET included: before, a page on another site could make the owner's machine write out an export.
- 2026-10-13: sign-in reads the forwarded scheme one way. `X-Forwarded-Proto: https,http` and `HTTPS` are https: the sign-in is accepted and the cookie is `Secure`. Before, a list signed in without `Secure` and upper case was refused.
- 2026-10-13: a connection nobody has vouched for is closed after three minutes of silence, and a sign-in whose body has not arrived after five seconds is answered 408 and closed. Before, a connection was never timed out, with or without a token. A request with a valid token, cookie or local session takes the timeout off its connection, so a reply that takes long (a write waiting behind a large report, an import) is not lost, and the change stream stays open. What remains: a client that is signed in may keep an idle connection open, as before.
- 2026-10-13: a session cookie that cannot be decoded is answered 401 and no longer 500 with a stack trace in the log. A failure that is not one of an operation's own refusals is answered `internal error`; its detail (a table, a path) goes to the log only. An actor name that starts with `forgotten-` is refused, for a token and for the owner at start-up: it is what a forgotten actor is called.
- 2026-10-13: `/healthz` names the commit the server runs: `{"ok":true,"version":"0.1.0","commit":"<40 hex>"}`, or `"commit":null` when the process was not told (issue #90, item 2). It reads `MAINWORTHY_COMMIT`, which an image holds when it was built with that build argument (`MAINWORTHY_COMMIT=$(git rev-parse HEAD) docker compose build`), and then `SOURCE_COMMIT`, which Coolify sets on the running container; anything but 40 lower-case hexadecimal characters reads as unknown, because the route needs no sign-in. `mainworthy health` prints the first 12 characters and `--json` gives the whole commit (`null` against a server that reports none).
- 2026-10-13: **documentation at `/docs`**, served by the instance and readable without an account (decision 0016). Twenty pages: how Mainworthy works, a quickstart, one page per workflow (cases, reports, the queue, runs, changes, agents), what can be customized (policy, people and tokens, configuration, data) and a reference (keys, commands, operations, glossary, troubleshooting), with ten interactive diagrams, search and both themes. In the app: **Docs** in the sidebar, or `g d`, opens the page about the current screen; the sign-in page links to the docs; the Keys overlay links to the screen's page, the palette finds a page when you type `docs` and a word, and each empty list and Settings section links to the page that explains it. The tables of commands, operations, capabilities, answers and presets are generated from the code (`bun scripts/gen-docs.ts`), and the check fails when the docs fall behind.
- 2026-10-13: every reply carries security headers; before, only the documentation's did, and in local mode any page the owner visited could show the signed-in workbench in a frame. The web UI's page runs under `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src 'self'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`, with no `'unsafe-inline'` and no `'unsafe-eval'`; every other reply (the API, the change stream, archives, `/mcp`, errors, the UI's script and style sheet) carries `default-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. All carry `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cross-Origin-Resource-Policy: same-origin`, `Cross-Origin-Opener-Policy: same-origin` over https and on this machine's own names (a browser ignores it elsewhere), and `Strict-Transport-Security: max-age=31536000` when the request came over https (by its scheme or the first element of `X-Forwarded-Proto`). The 500 reply is written without the request, so it carries neither of those two. **Changed:** the app can no longer be shown in a frame, by any page; the UI's script, style sheet and icon are sent with `Cache-Control: public, max-age=31536000, immutable` and the page with `no-cache` (the executable sent neither); a request to a path of the web UI with a method other than GET or HEAD is answered 405, where the executable answered with the page. A start from source without `NODE_ENV=production` serves Bun's development bundle under the same policy plus three things that bundle needs: the hash of Bun's one inline script, `blob:` scripts for hot reload, and inline styles for the error Bun shows in the page. That bundle's reload socket opens only for the server's own page: another site's page, a page on another port of the same machine and a name that is not this machine's are answered 403 (the reply that opens the socket, a 101, is the one reply with no security headers: a browser applies none to a socket). The documentation at `/docs` keeps the policy of its own pages and its `Referrer-Policy: same-origin` (a page frames its diagrams, so its framing header is `SAMEORIGIN`) and gets the other headers. What each header is for and how the UI's files come to carry them: `docs/architecture.md`, "What every reply carries".
