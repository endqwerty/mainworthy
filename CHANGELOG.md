- 2026-10-12: a pipeline's token records results and reads the gate, and nothing else (decision 0014). New capability `record`, which `produce` includes; `casebook token new --ci <name>` grants it alone. A pipeline (`ci`) actor holds `read` and `record` at most, whatever its grant says: before this, the documented pipeline token (`--can read,produce`) could create and change cases under `loose` and `standard`. **Changed:** a `ci` token made with `produce` keeps reporting and can no longer propose, claim or decide; `token new` for an actor that exists no longer replaces its grant (naming the grant it holds is accepted, another is refused); a caller that may not run an operation gets `forbidden` before its input is checked; the session lists every project the caller holds a grant on, and `can` of a producer now includes `record`. **New:** `casebook actor list | grant | ungrant` and the `admin` actions `grant.set` and `grant.remove`; `actor.list` shows each grant with its project.
- 2026-10-12: this repository's CI can report to a deployed instance (decision 0014; set-up in docs/deploy.md, switched on in #92). The `gate` job joins the tailnet when the repository says how, uses the instance `CASEBOOK_URL` names when it answers, speaks the same `report` and `gate` and accepts the token, and otherwise starts its own Casebook for that run; a refused token fails the job. The run's summary page says which Casebook decided. Backlog: #88 (sign-in and token hardening), #89 (the instance fetches reports), #90 (the instance follows main), #91 (agents on their own tokens).
